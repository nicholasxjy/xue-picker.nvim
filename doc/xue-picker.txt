*xue-picker.txt*  Bottom picker                                  *xue-picker*

Requires Neovim 0.12+, vim._core.ui2, ripgrep, and an attached Neovim UI.

Commands                                                        *:XuePicker*
    :XuePicker [name]        Defaults to smart; supports name completion.
    :XuePicker resume        Restores query, selection, and preview; refreshes data.
    :checkhealth xue-picker  Checks dependencies, native library, and last fallback.

API                                                         *xue-picker-api*
    require("xue-picker").setup(opts)
        Optional. Precedence: built-in -> defaults -> pickers[name] -> call options.
        Records merge field by field; lists are replaced as a whole.
        See doc/default-config.lua for all defaults.

    require("xue-picker.builtin").NAME(opts)
        NAME: files, smart, buffers, live_grep, grep_word, diagnostics, marks,
              oldfiles, git_files, history, manpages.
        cwd defaults to the working directory at the time of the call;
        hidden=true, ignore=true, follow=false.
        File and location results support multiselect. Accepting multiple items
        populates and opens quickfix.

    require("xue-picker").pick(opts) -> session
        opts.items: candidate array, or opts.source(ctx, emit): asynchronous source.
        Candidate fields: id (stable), text, path, lnum (1-based),
        col (0-based byte offset).
        idx controls stable ordering; the matcher sets score.
        Candidate arrays are not deep-copied.
        source returns a cancellation function;
        ctx contains query/cwd/generation/session.
        emit(items, state) appends by default; replace=true replaces results,
        and done=true marks completion.
        state.error displays an error. Output from closed sessions or stale
        generations is discarded.
        live=true refreshes the source on query changes; debounce_ms sets the delay.
        matcher(query, items, checkpoint) -> matched candidate array.
        format(item, ctx) -> text, { {start_byte, end_byte, hl_group, priority?}, ... }
        priority defaults to 150.
        Formatting applies only to visible rows; all ranges are [start, end).
        on_accept(items, action, session) runs after closing and restoring windows.
        on_close(session) runs on close; session.accepted indicates acceptance.
        actions[name](session) defines a custom action; keymaps[name] binds it.
        file_actions=true enables splits/preview;
        multiselect=true enables multiple selections.

    session:close()          Closes, cancels work, restores window/view/cmdheight.
    session:refresh()        Requests data again.
    session:set_query(text)  Updates input and matches; cancels previous source work.
    session:get_selection()  Returns selected items, or an array with the current item.
    require("xue-picker").resume()
        Restores the most recent resumable session.
        ui_select/ui_input sessions are excluded from resume.

Statusline                                            *xue-picker-statusline*
    statusline=true by default. While open, a global statusline displays the
    picker name, matched/total counts, selected count, backend, and loading,
    searching, error or truncated state. The previous 'laststatus' is restored
    on close, accept, replacement or failed opening. Existing global and
    window-local 'statusline' definitions are preserved. A 'laststatus' value
    changed by the user while open is retained.

    lualine.nvim: add "xue-picker" to your existing extensions list: >lua
        require("lualine").setup({ extensions = { "xue-picker" } })
<   Keep statusline=true. Supports globalstatus=true and false, uses the lualine
    theme, and refreshes on picker state changes. XuePicker must be on the
    runtime path when lualine loads the extension. If using ignore_focus,
    allow focus on the xue-picker-input filetype.

    For custom statuslines, defaults.statusline=false disables the built-in
    display and leaves 'laststatus' unchanged. Per-picker and per-call overrides
    also accept statusline=false. The API and update event remain available.

    require("xue-picker").statusline() -> string
        Plain text component; returns "" when closed. A native statusline can
        include: %{v:lua.require("xue-picker").statusline()}
        Use %{} (without recursive evaluation) to preserve literal percent signs.

    require("xue-picker").status() -> table or nil
        Fresh snapshot, nil when closed. Fields: name, cwd, query, index
        (1-based, 0 when empty), count (matched), total, selected (count),
        loading, searching, error, truncated, backend.

    User XuePickerUpdate
        Fires on opening, rendered state changes and closing. Read status()
        inside the callback; nil means closed. Updates follow performance.render_ms;
        unchanged renders do not repeat the event. The lualine extension handles
        this event automatically.

Builtins                                                *xue-picker-builtin*
    files: Directory files, without history.
    smart: Combines directory, open, and valid recent files;
        deduplicates by absolute path. filter.cwd=true, matcher.frecency=true.
    buffers: Listed buffers, including unnamed and terminal buffers.
        The current buffer is included even if unlisted. Quickfix and the
        picker's own buffers are excluded. show_unlisted=true includes other
        unlisted buffers; show_unloaded=true by default.
        Rows match fzf-lua: [number], four flag columns, icon, path:line.
        Numbers align across all candidates. Flags: % current, # alternate,
        a visible/loaded, h hidden, = read-only, + modified.
        sort_lastused=true pins the current buffer in a fixed, non-selectable
        header; other buffers use recent-first order, with the alternate first.
        Filtering, selection and result counts exclude the header. If only one
        result row fits, the header is hidden to keep the selection visible.
        sort_lastused=false makes the current buffer selectable;
        ignore_current_buffer=true excludes it entirely.
        path_format="relative" and git.enabled=false by default.
        filename_first displays filename directory:line, with separate path
        highlights. filename_only=true displays/searches only the filename,
        without icons or line numbers. Unnamed buffers display [No Name];
        URI labels are preserved, and terminals use their terminal title.
        Narrow rows truncate with fzf's two-dot ellipsis and scroll horizontally
        to keep query matches visible. Selection uses fzf's bold text, gutter,
        marker and background, leaving the right margin clear.
        Saved line numbers guide previews; accepting preserves cursor position.
        delete protects unsaved changes by default; force=true allows deletion.
    live_grep: regex/plain, smartcase, grouped by file. See |xue-picker-grep|.
    grep_word: Opens live_grep with <cword> from the invoking buffer, respecting
        'iskeyword'. Uses mode="plain" by default; accepts live_grep options
        and inherits setup.pickers.live_grep settings. The query remains editable.
        Pass mode="regex" to interpret the word as a regex. query is always taken
        from the cursor; an absent word opens an empty query.
        Example: require("xue-picker.builtin").grep_word({ cwd = "~/project" })
        Command: :XuePicker grep_word
    diagnostics: scope="workspace"/"buffer"/"cwd"; passes through bufnr and severity.
        severity follows |vim.diagnostic.get()|. sort=true or 1 (default) orders
        Error/Warn/Info/Hint; sort="reverse" or 2 reverses severity order.
        Equal severities are ordered by buffer/line/column, with stable ties.
        sort=false preserves vim.diagnostic.get() order. A function receives
        (diagnostics, opts) and returns an ordered diagnostic array.
        Filtering preserves this order. Set setup.pickers.diagnostics.sort
        or pass sort per call.
        Rows match fzf-lua: sign, [source], file:line:column:, message, [code].
        filename_first displays filename directory:line:column: in the heading.
        multiline=2 (default) puts messages below headings with one blank row
        between entries; true removes the gap. false displays a compact row
        using the first message line. Long rows wrap without splitting UTF-8.
        Signs follow vim.diagnostic.config().signs.text, falling back to E/W/I/H.
        diag_icons=false uses these letters; a severity-indexed table overrides
        the symbols. signs.Error/Warn/Info/Hint accepts {text=..., texthl=...}.
        diag_source, diag_code, color_icons, color_headings default to true;
        file icons and Git status are disabled by default.
    marks: Global marks and local marks from the invoking buffer; unfolds on jump.
    oldfiles: Excludes invalid entries; filter.cwd=true restricts the scope.
    git_files: Tracked files; untracked=true includes untracked files.
    history: type="cmd" restores the command line for editing;
        type="search" repeats the search.
    manpages: Asynchronous man -k .; opens through :Man.

Keymaps                                                 *xue-picker-keymaps*
    next       <C-n> <Down> <Tab>    previous    <C-p> <Up> <S-Tab>
    accept     <CR> <C-y>           close       <Esc> <C-c>
    split      <C-s>                vsplit      <C-v>
    tab        <C-t>                toggle      <C-x>
    toggle_all <C-a>                delete      <C-d>
    preview    <C-o>                refresh     <C-r>

    Accepts a string or list of strings; false / {} disables an action's mappings.
    Overriding an action replaces all of its keys.
    Mappings apply only in insert and normal mode in the input buffer;
    only supported actions are bound.
    Duplicate keys for the same action are removed. Conflicts between actions
    raise an error before opening. Hints reflect the actual mappings.
    Bottom hints match fzf-lua's action headers:
        :: <ctrl-s> to split|<ctrl-x> to select
    The row has two leading spaces and reserves one column on the right.
    Each binding has its own entry, sorted by key, including aliases.
    Only the key text inside <...> uses XuePickerHintBind; action names use
    XuePickerHint. Brackets, " to ", the prefix and | use XuePickerHintSeparator.
    Narrow rows truncate with fzf's two-dot ellipsis, preserving Unicode and
    the colors under the replaced cells. Hints for open, close, next, previous, preview,
    and refresh are hidden while their shortcuts remain active.
    On error, the hint bar displays only the error message.
    Buffer deletion is labeled "close", matching fzf-lua.
    hint=true shows the hint bar by default. defaults.hint=false hides it globally;
    pickers.live_grep.hint=false hides it for that picker. Individual calls also
    accept hint=false. Hiding the bar gives its row to results/preview;
    shortcuts remain active.

    Hint groups prefer FzfLuaHeaderBind, FzfLuaHeaderText and FzfLuaFzfHeader.
    When these are undefined, keys use BlanchedAlmond (dark background) or
    MediumSpringGreen (light); action names use Brown1 (dark) or Brown4 (light).
    Separators fall back through FzfLuaTitle, FzfLuaNormal and Normal.
    No fzf-lua dependency is required. Existing theme definitions and explicit
    XuePicker highlight overrides are preserved; defaults refresh on ColorScheme
    and picker opening.

Queries                                                   *xue-picker-query*
    foo bar       AND             foo | bar       OR
    !test         Exclude         'foo            Exact substring
    'foo'         Whole word      ^foo / lua$     Start/end anchors
    file:lua$     Field filter    foo.lua:10:3     File location

    Default smartcase follows the reference implementation's ASCII case rules.
    Matching and scoring use UTF-8 bytes; highlights cover complete characters.
    Ordering: score descending, text byte length ascending, original idx ascending.
    Filename/cwd/frecency bonuses are configurable.
    history_bonus and Git bonuses are disabled by default.
    Frecency defaults to a 30-day half-life and at most 10,000 entries,
    with delayed atomic writes to:
        stdpath("data")/xue-picker/frecency.json

Grep backends                                              *xue-picker-grep*
    Defaults for pickers.live_grep:
        backend="auto", fallback=true, mode="regex", smartcase=true,
        debounce_ms=80, max_results=20000, max_file_size=10485760,
        globs={}, ripgrep={cmd="rg", args={}},
        fff={page_size=256, time_budget_ms=8, ready_timeout_ms=150,
             request_timeout_ms=1000, idle_timeout_ms=60000}

    auto prefers fff and falls back to rg when unavailable or on initialization/
    request timeouts and errors. backend="fff" also allows fallback by default;
    fallback=false displays the error and keeps the panel open.
    backend="ripgrep" uses rg directly. After fallback, the current session keeps
    using rg; the next session checks again.
    Fallback replaces results instead of appending. No results, empty queries,
    and cancellation do not trigger fallback.
    Invalid regex queries display an error without literal fallback.

    fff is optional and must provide content_search()/file_search() and its native
    library. Synchronous searches run in an isolated headless Neovim worker,
    with pagination over asynchronous RPC.
    Workers load neither user init nor plugin entry points, use isolated config
    and cache directories, and are recycled when idle.
    The fff picker UI is not invoked; fff is not installed or compiled automatically.

    fff constraint syntax can change query semantics. Queries with whitespace,
    git:, ! / * ? { }, custom globs, nondefault scan scopes, and extra rg options
    are routed to rg. Disabling fallback produces an explicit error in these cases.
    ripgrep.args must not override the JSON/mode/output contract.
    All backends return 1-based line numbers, 0-based byte columns, and
    [start,end) match ranges.
    live_grep icons and file paths share the group heading. Each match row starts
    with right-aligned line:column fields, each sized to the largest number of
    digits in the current results. Displayed lines and columns are 1-based.
    Widths stay consistent while scrolling and update when new results arrive.
    Line numbers use XuePickerLineNr; columns use XuePickerColNr.
    Custom path_format callbacks format file-path headings.
    live_grep and grep_word highlight the entire header path with
    XuePickerGrepPath, linked to FzfLuaFilePart by default.

UI and preview                                               *xue-picker-ui*
    Prompts follow fzf-lua's default-prompt profile:
        files/smart: cwd path ending in /; cwd_prompt=false uses Files> .
        buffers: Buffers> ; live_grep/grep_word: Grep> ; diagnostics: Diagnostics> .
        marks: Marks> ; oldfiles: Oldfiles> ; git_files: GitFiles> ; manpages: Man> .
        history: Command history> or Search history>, depending on type.
        ui_select: Select one of> ; ui_input: Input> ; custom pick: > .
    Cwd parent components are shortened after cwd_prompt_shorten_len=32 bytes,
    retaining cwd_prompt_shorten_val=1 characters per parent component.
    An explicit prompt overrides the cwd prompt. Global, picker, and call-level
    prompt overrides follow normal precedence. ui_select converts a caller's
    trailing colon to > ; ui_input preserves the supplied prompt.
    Prefixes use XuePickerPrompt. Typed input uses XuePickerQuery, except
    live_grep/grep_word use XuePickerLivePrompt. Input highlight callbacks take
    priority over the default query color.
    The fixed prompt and editable query occupy separate parts of the input row.
    Empty input and Home place the cursor after the prompt; initial/resumed text
    places it at the end. Long queries scroll while the prompt stays fixed.
    Narrow layouts clip the prompt to keep input space available. Pasted input
    stays on one line; highlight callback byte offsets refer only to the query.
    layout.height=0.4, max_height=18. The full-width bottom panel contains
    input/results/hints.
    preview.enabled=false. Wide layouts place preview beside results; narrow
    layouts stack them. Preview is hidden when there is insufficient space.
    Preview prefers loaded buffers, otherwise reads files asynchronously;
    defaults are 1 MiB and 2,000 lines.
    Binary or oversized files display an explanation; rapid selection changes
    discard stale results.
    performance.slice_ms=4, render_ms=16, preview.debounce_ms=60.
    cache_dirs=3, cache_entries=200000. Reopening shows cached results and rescans.
    icons="auto" detects mini.icons / nvim-web-devicons; false disables icons.
    Icons use the provider's highlight group; icons(item) can return text and a
    highlight group. Returning only text uses XuePickerIcon.
    XuePickerFilename highlights filenames in file lists, location paths, and
    group headings. Match highlights take priority over filename colors.
    path_format="filename_first" / "relative" / function(item,cwd).
    With filename_first, files/smart place the filename and status on the left,
    followed by the directory. Directory right edges align to the longest visible
    filename/status/directory combination without adding space as the window grows.
    Alignment uses display width and leaves at least two spaces before directories.
    Custom path_format output receives path highlights;
    format callbacks provide their own highlight ranges.

    Highlight groups (all prefixed with XuePicker): Normal, Prompt, Query,
    LivePrompt, Match, Icon,
    Filename, Directory, LineNr, ColNr, Selected, Marker, Hint, HintBind,
    HintSeparator, Count, Error, Git, Group, GrepPath, PreviewLine, Border,
    DiagnosticError, DiagnosticWarn, DiagnosticInfo, DiagnosticHint, DiagnosticCode.
    All default definitions are exported in defaults.highlights and
    doc/default-config.lua.
    Default links to fzf-lua groups (left names have the XuePicker prefix):
        Normal       -> FzfLuaNormal
        Prompt       -> FzfLuaFzfPrompt
        Query        -> FzfLuaFzfQuery
        LivePrompt   -> FzfLuaLivePrompt
        Match        -> FzfLuaFzfMatch
        Icon         -> FzfLuaNormal (when the provider returns no group)
        Filename     -> FzfLuaFilePart
        Directory    -> FzfLuaDirPart
        LineNr       -> FzfLuaPathLineNr
        ColNr        -> FzfLuaPathColNr
        Selected     -> FzfLuaFzfCursorLine
        Marker       -> FzfLuaFzfMarker
        Hint         -> FzfLuaHeaderText
        HintBind     -> FzfLuaHeaderBind
        HintSeparator -> FzfLuaFzfHeader
        Count        -> FzfLuaFzfInfo
        BufferNumber -> FzfLuaBufNr
        BufferCurrent -> FzfLuaBufFlagCur
        BufferAlternate -> FzfLuaBufFlagAlt
        BufferLineNr -> FzfLuaPathLineNr
        BufferHeader -> FzfLuaFzfHeader
        BufferSelected -> FzfLuaFzfCursorLine
        BufferMatch  -> FzfLuaFzfMatch
        BufferPointer -> FzfLuaFzfPointer
        BufferMarker -> FzfLuaFzfMarker
        Group        -> FzfLuaHeaderText
        GrepPath     -> FzfLuaFilePart
        PreviewLine  -> FzfLuaCursorLine
        Border       -> FzfLuaBorder
        DiagnosticError -> DiagnosticSignError
        DiagnosticWarn  -> DiagnosticSignWarn
        DiagnosticInfo  -> DiagnosticSignInfo
        DiagnosticHint  -> DiagnosticSignHint
        DiagnosticCode  -> Comment
    Error -> DiagnosticError, Git -> DiffChange (no equivalent fzf-lua groups).
    BufferGutter uses FzfLuaFzfGutter's background as its foreground, falling
    back to Normal's background. BufferStrong supplies bold text.
    Buffer groups use matching fzf-lua dark/light defaults when targets are
    absent, preserving theme and explicit configuration overrides.
    Target groups are defined by the colorscheme or fzf-lua;
    this plugin does not load fzf-lua automatically.
    Definitions use default=true to preserve existing settings and respond to
    ColorScheme while the picker is open.
    defaults.highlights accepts full group names and nvim_set_hl() options: >lua
        require("xue-picker").setup({
          defaults = {
            highlights = {
              XuePickerMatch = { fg = "#ff9e64", bold = true },
              XuePickerSelected = { link = "Visual" },
            },
          },
        })
<   Each group definition is replaced as a whole, including link/default fields;
    unspecified groups remain inherited.
    Picker and per-call overrides follow the same precedence as other options.
    Highlight definitions apply globally when the picker opens;
    overrides can use default=true to preserve existing definitions.

vim.ui                                                   *xue-picker-vim-ui*
    builtin.ui_select(items, opts, on_choice)
        Returns the original item and its 1-based original index;
        cancellation calls back with nil,nil.
        Preserves duplicate values and original objects;
        supports format_item/prompt/preview_item.
    builtin.ui_input(opts, on_confirm)
        Supports prompt/default/completion/highlight;
        accepting an empty string is distinct from cancellation with nil.
        With completion, Tab inserts the current candidate.
        Supports custom/customlist.
    Both invoke the accept/cancel callback exactly once.
    Global replacement is disabled by default; enable explicitly:
        require("xue-picker").setup({ui={select=true,input=true}})

Testing                                                 *xue-picker-testing*
    make test           Lua integration tests in isolated Neovim with attached UI.
    make lint           StyLua + Lua syntax checks.
    make differential   Pinned 241e22c reference; set XUE_REFERENCE to its checkout.
    make ui             Python/pynvim attached UI and screen snapshots.
    make perf           Fixed 20,000/100,000-candidate matching benchmarks.
    make perf-ui        First display, cache, and real 20,000-file disk benchmarks.
    NVIM, STYLUA, and PYTHON override command paths.
    fff failure tests use controlled doubles through real worker/RPC;
    they do not measure native-library performance.
    See doc/performance.md for methodology and limitations.
